## 阻塞与下一轮验收

1. CeShi 不是 GLM 所属企业的管理员；没有权限在 `/user` 停止共享 GLM。需要一次明确的临时成员授权确认。已上线可审计、可二次确认的精确成员撤销路径；测试结束要立即撤销，不依赖手动口头承诺。
2. 现有 5002/5003 浏览器页保留旧会话内容，不代表当前 Code 仍可调用。需由对应账户从 `/user` 重新取得有效工作区交接，再实测“发消息 → 回复 → 停止 → 再次启动 → 文件保留”。
3. GLM 停止后，先从 UI 验证 `.178/.179` 不再占用，再决定是否在 `/mana` 恢复 `.179` 调度。不能仅凭 GPU 利用率 0% 推断空闲。
4. 目前 CeShi 没有独占机器访问或有效工作区权限，因此 IaaS 实例启动/停止、PaaS 关闭/重开和 MaaS 停止尚未完成真实业务闭环验收。
