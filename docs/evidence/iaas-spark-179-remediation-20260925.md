# DGX Spark .179 IaaS 实测整改记录（2026-09-25）

本轮只针对上一轮公网企业端 IaaS 验收暴露的故障。没有创建、付款或激活真实订单。
`.176/.177` 试用节点及 ComfyUI 5005 未参与节点滚动。

## 已确认的故障与代码整改

| 现场现象 | 根因 | 整改 |
| --- | --- | --- |
| `.179` 已标记企业专属池，但容量仍为零 | 节点代理只在启动时读取 ConfigMap inventory；已挂载的新标签没有进入签名心跳 | 每次心跳重新读取并核对节点身份，ConfigMap 更新后无需重启才能生效 |
| GLM 占用 `.179` 约 111 GiB 统一内存，门户却显示可租 | 商品容量只比对声明的总内存和健康 GPU | GB10/SM121 商品要求新鲜的实测可用主机内存至少达到总内存的 95%；缺报、过期或占用则不可售 |
| 受管申请缺少生效协议时显示“资源状态已变化” | 浏览器请求层丢弃 API 错误码；所有 409 被归为同一提示 | 保留受限格式的错误码，针对 `AgreementRequired` 给出协议入口；缺协议时表单预先提示并禁用提交 |
| 自助下单条款缺失只显示不可用 | 生产没有发布经审核的 `machine-self-service` 模板 | 说明必须由平台发布经审核条款，保留下单关闭闸门；不以演示模板冒充法律文本 |
| 自助 SKU 按秒计价易与承诺函 ¥49/天混淆 | 两条产品路径有独立商品与审批流程 | 在自助裸 GPU 卡片说明价格不是承诺函档位；没有自动改写已存在的金融报价 |

## 验证边界

- 原生 MoonBit 全套测试 `1233/1233`、JS 测试 `629/629` 通过，新增了繁忙/过期统一内存、动态 inventory 和协议缺失的回归测试。
- 企业端新 bundle 已在公网 `/user/enterprise.js` 与构建 SHA-256 `af6d2df18b8ba7c79f733d6f6d4c44413cd79f218476f66b1bdb2a8b63b1937b` 对上，部署可回退到前一镜像。
- 控制器新镜像从集群仓库按 digest `sha256:f50885ecfe2a60edb578e8b95c37e983db41d9b7454e9a40ead265681f645a6d` 拉回后上线；Deployment `1/1`，节点遥测继续收到 HTTP 202。公网企业端在升级后显示无可售 IaaS 容量，且没有创建订单。
- 公网 `/mana/`、`/user/`、`/docs/` 与试用 ComfyUI `:5005/` 均返回 HTTP 200；管理端节点页仍显示四台真实 Spark 的近期统一内存。测试账户在企业端可登录，缺协议的受管申请有明确提示且提交按钮禁用。
- 控制器切换后，GLM 双机服务从 `.178:8888` 的 OpenAI 兼容接口完成一次真实聊天请求，返回 `content="OK"` 与 `finish_reason="stop"`；这仅验证该服务未被本轮控制器更新破坏，不构成 IaaS 订单验收。
- 节点代理的 inventory 热重载代码尚未滚到四台 Spark；本次已通过重启 `.179` 代理使当前标签进入心跳。后续代理镜像发布应先在非试用节点做逐台验收，不能打断 `.176/.177` 的试用工作负载。
- 当前 `.179` 保持平台侧隔离，不作为新 IaaS 可售容量；其上的 GLM 双机服务不应为了验证库存而被无声终止。
- 正式 IaaS 下单仍需要经审核的机器自助条款或已执行的组织协议，以及真实付款/授权。演示企业不能代表商业验收。

## 价目边界

承诺函路径来自经单独审核的文书，日/周/月档位为 ¥49/¥322/¥1290；机器自助 SKU 的 `CNY 0.02/second` 是另一条线上商品。两者同时存在不自动构成算术错误，但在正式上架前，平台应明确决定是否保留这套独立自助价目；没有这个商业决定，不应偷偷把任何一方改价。
