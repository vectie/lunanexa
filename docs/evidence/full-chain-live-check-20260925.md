## 运行时诊断（只读，不代替 UI 验收）

- Kubernetes 中控制器、企业端、身份网关、PostgreSQL、四个节点代理、FL2VA 和 REF2VA Pod 均为 Running；这证明进程状态，不证明推理产出。
- 5005 上一轮 UI 的新视频任务失败后，FL2VA 日志显示 `diffusion_engine.py` 在等待扩散输出时触发 30 秒 `asyncio.TimeoutError`；随后记录 `Aborted request(s)`，`DELETE /v1/videos/<job>` 返回 200。到本轮检查时未见新的视频生成请求或成功结果。本轮没有重复提交任务或重启 `.176/.177`。
- 代码中的企业 GLM 控制接口目前仅提供状态查询与 `:stop`；没有相应 `:start`，所以无法宣称“用户从已停止状态重新启动 GLM”已通过。
- 本轮源码回归：`moon test --target native` 为 **1238/1238**，`moon test --target js` 为 **634/634**。这些测试不替代真实 GPU、浏览器、支付或模型推理验收。
- 本测试浏览器的标准 443 入口打开 `/mana/` 返回 `ERR_TUNNEL_CONNECTION_FAILED`；同域名 8443 正常。该错误来自本测试浏览器的网络隧道，不足以断言用户侧 443 不可达；本轮所有业务 UI 观察均走 8443。
