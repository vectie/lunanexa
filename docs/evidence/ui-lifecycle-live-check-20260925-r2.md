## 根因与修复

1. 企业管理员只有 `OrganizationAdministrator`，但浏览器在读取共享模型状态前先拉取个人交付列表；后者要求 Developer，失败后模型卡完全消失。现在独立处理个人交付列表错误，共享模型状态及停止按钮仍可读取；失败时面板显示状态错误和刷新按钮。
2. Kubernetes 的 GLM 控制密钥与宿主控制程序使用同一份文件，但该文件末尾有换行。控制程序读取时去掉换行，控制器原样发送，导致 503。现场 Secret 已去掉末尾换行，控制器滚动重启并实测恢复；源码也对环境密钥 `trim()`，防止下次配置生成重现。
3. 两张同名 DGX Spark 卡片仅显示相同 SKU 和价格，用户无法区分。现显示稳定的配置编号；这仍是抽象销售配置，不等于用户能精确指定 `.179` 物理节点。
4. 对没有企业共享模型的租户，控制接口的 `404 NotFound` 表示“不适用”，不是模型故障；浏览器现将其与真正的 503 状态错误区分。CeShi 原有试用组织复测未显示错误的 GLM 卡或 404 告警。
