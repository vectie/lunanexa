# 两端页面精简与权责核对

更新：2026-11-08。验收目标仅为正式 `/user/`、`/mana/`；不以 demo 验收。

## 统一原则

默认层回答“现在怎样、下一步做什么”。需要决定时再展开输入；技术证据、
历史和少用设置留在有名称的详情中。异常、费用、授权范围、签署和破坏性操作
的后果应在相关操作处可见，不用折叠来掩盖阻塞或改变权限。

用户负责自己的申请、资料、签署、凭据和已授权资源使用；企业管理员邀请本企业
成员。运维负责企业审核、平台授权、物理资源分配、模型发布、运维和故障处理。
两个入口使用同一资源与服务归属，不建立第二份部署权威。

状态区分：**已修正**表示代码与测试完成；**已上线复核**另记正式站点证据；
**沿用已简化布局**不代表本轮重写；**待改**必须保留具体剩余场景。

## 后续按页推进

1. 后端游标：本轮分页限制实际构造的行与卡片，现有快照 API 仍一次返回记录；后续单独优化查询传输量，不宣称已有服务端分页。
2. 异常物理验收：不为验收主动破坏运行中模型或触发真实租约清理。相关界面与状态机回归验收和实际故障演练分别记录。
3. 新企业与多组织：本轮补齐状态/交接与隔离回归，正式站点的新身份注册、创建企业、审核和邀请会产生真实业务或新权限，不用现有单企业账号冒充完整生产演练。
4. 小屏和键盘：逐页检查首屏、展开/收起、焦点、表格滚动和弹窗返回。

性能要求：本轮使用原生 `details`，不新增轮询、请求或推理路径。权限记录只为
所选人员构造卡片，避免默认构造全部里程碑；底层授权数据仍由既有 API 返回。
后续分页应减少实际渲染与查询量，不只把长表藏起来。

## 第二轮：分页、异常交接与企业范围

本轮代码覆盖：

- 六类列表每页仅构造 25 条；搜索和翻页相互独立，搜索重置页码，刷新缩减记录不会停在空白页。请求与审计按最新优先排列。
- 用户能处理的超时与需要平台管理员处理的制品/模板异常分别引导；保留原交付标识、故障信息复制和修复后的同记录重试。没有新增服务端拒绝条件。
- 创建企业和加入企业都会更新请求代次；加入邀请不再丢弃服务端返回的企业归属。已选企业消失时不静默换到另一家企业。
- 切换或失去企业成员关系，先清除旧企业密钥、合同、费用、机器、服务、付款和应用投影，再加载新企业。相同企业刷新保留未完成订单和草稿。
- 多企业未选中时先提供企业选择；注册/加入在次级展开中。拒绝、停用和关闭的企业不会显示为等待审核；待审核阶段继续核对企业状态，不先进入应用就绪检查。

验收按层记录：编译/测试、部署文件、公网字节、正式登录态交互、真实新企业业务演练；后两层不由单元测试替代。本轮不新增验收企业、成员、密钥或订单。
