# 两端页面精简与权责核对

更新：2026-11-10。验收目标仅为正式 `/user/`、`/mana/`；不以 demo 验收。

## 统一原则

默认层回答“现在怎样、下一步做什么”。需要决定时再展开输入；技术证据、
历史和少用设置留在有名称的详情中。异常、费用、授权范围、签署和破坏性操作
的后果应在相关操作处可见，不用折叠来掩盖阻塞或改变权限。

用户负责自己的申请、资料、签署、凭据和已授权资源使用；企业管理员邀请本企业
成员。运维负责企业审核、平台授权、物理资源分配、模型发布、运维和故障处理。
两个入口使用同一资源与服务归属，不建立第二份部署权威。

状态区分：**已修正**表示代码与测试完成；**已上线复核**另记正式站点证据；
**沿用已简化布局**不代表本轮重写；**待改**必须保留具体剩余场景。

## 实现清单（本轮关闭）

1. 服务端游标：账户、工作区档案、授权、所选人员企业权限、审计、请求回执每次最多 25 条；列表加载不再请求对应完整快照。审计固定浏览上界，其他列表变动自动回第一页，保留查询；旧响应不得覆盖当前人员/查询/会话。
2. 异常交接：原记录重试、平台修复、复制故障/服务引用分别可达；本轮新增部分服务/不可用交接。物理故障演练与界面实现分开验收，不主动破坏运行中模型。
3. 新企业与多组织：注册/审核/邀请/跨企业隔离已有原生 HTTP 回归；加入、选择、失去成员关系与旧请求隔离已修正。正式生产新企业演练仍是独立验收，不以单企业会话或 fixtures 冒充。
4. 小屏和键盘：紧凑应用卡片、表格横向键盘滚动、可见焦点、44px 控件、长弹窗滚动；两端共用弹窗处理，模态 Tab/Shift+Tab 约束焦点，关闭返回触发按钮，Escape/遮罩只调用明确取消按钮，不触发确认。非模态确认面板不锁住背景导航。

性能：保留原生 `details`，无新增轮询或推理路径。筛选和计数仍扫描现有内存快照；
服务端只投影/传输当前页，企业权限先按人员筛选，浏览器不再下载所有里程碑。
人员选择另取轻量元数据，翻页不会丢失授权对象。节点归属为既有刷新增加一次小型
台账读取，不调用模型健康探针。不要宣称底层已改为数据库索引游标。
